# Authority Model

Priority and quality are separate fields. Priority describes how strongly a record applies to the current task; quality describes the evidentiary status of its source.

| Priority | Meaning |
|---|---|
| critical | Must be followed for the route unless the current task explicitly changes it. |
| high | Strongly applicable derived or verified guidance. |
| medium | Useful context when selected. |
| low | Supporting reference. |
| archival | Provenance or historical material only. |

| Quality | Meaning |
|---|---|
| authoritative | Current project instruction or canonical project decision. |
| verified | Directly supported by a supplied or current verified source. |
| useful_reference | Selected example; never a command. |
| experimental | Proposal requiring explicit acceptance. |
| uncertain | Evidence incomplete or access-limited. |
| obsolete | Retained only to explain history. |

When sources conflict: current task instruction, canonical decision, current relevant UX4G/GIGW requirement, verified project source, current official EPFO information, supporting reference, historical material. Serious conflicts are recorded in `11_RETRIEVAL/CONFLICT_RESOLUTION.md`.
